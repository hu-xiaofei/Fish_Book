# FishBook：OSS 私有照片接入设计

日期：2026-09-12

状态：设计已获用户审阅批准，实施中；2026-09-12 用户批准下述学习环境数据库 TLS 例外。

## 1. 目标与范围

将生产环境的钓获照片存储接入阿里云 OSS，同时保持既有所有权校验、上传限制、照片替换与删除补偿机制。保留本地 MinIO 开发和测试环境，不改变前端 API 或数据库表结构。

整个上线工作拆为三个子项目，本文仅设计第一个：

1. OSS 存储适配器、配置选择、自动化测试及接入手册。
2. ECS 部署配置、RDS 连接（正式业务要求加密，学习环境例外见第 8 节）、镜像交付和非公开验收环境。
3. 域名与备案完成后的公开 HTTPS 发布、备份恢复演练及发布回滚。

本文不授权创建 Bucket、变更 RAM 权限、产生新费用或执行线上数据写入。实际开通与权限变更前，单独确认目标资源、收费规则及操作范围。

## 2. 已有条件与阻碍

- 后端通过 `MediaStore` 的 `put`、`get` 和 `delete` 接口使用媒体存储。
- 当前启用媒体时固定创建 MinIO 客户端；未启用时使用 `DisabledMediaStore`。
- `MediaProperties` 的启用校验要求 MinIO Endpoint、AccessKey、SecretKey 和 Bucket。
- 既有清理任务调用同一个 `MediaStore`，具有失败重试机制。
- 本地 Compose 启动 MySQL 和 MinIO，不可直接当成生产部署文件。
- 上一轮已通过严格主机指纹校验登录 ECS，并安装验证容器引擎与 Compose。这不是本文编写时的再次复测。
- RDS 内网端口上一轮可达，但初始握手未声明 TLS；用户提供的工单回复（2026-09-12 11:45:58）确认本地盘 MySQL 8.4 暂不支持开启 SSL。未在本文更新时重新检查云端。
- 域名、备案暂缓，不能把非公开部署准备宣称为正式上线。
- OSS 是否已开通、Bucket 与实例角色是否存在尚未核实。实现时不能假设资源已经存在。

## 3. 方案选择

采用阿里云原生 OSS Java SDK V1 实现独立适配器，不把现有 MinIO 客户端仅更换 Endpoint 后视为已验证的 OSS 集成。

备选方案是复用 S3 兼容协议，改动较少，但仍需验证签名、错误映射和凭证刷新行为。原生适配器可以明确地使用 ECS 实例角色和 OSS 语义，故本项目优先采用原生 SDK。

SDK 及凭证工具使用实施时核实的固定版本；不使用 `LATEST` 或动态版本。检查依赖树、Java 21 兼容性及依赖安全公告后锁定版本。

## 4. 组件和配置边界

- 保持 `MediaStore`、`StoredMedia` 和公开 API 不变。
- 增加 `OssMediaStore`，只负责对象上传、读取和幂等删除，不处理用户身份或创建云资源。
- 增加存储提供方选择 `fishbook.media.provider`：支持 `minio` 和 `oss`；省略时仍兼容现有本地 MinIO 配置。
- 媒体关闭时，只创建不可用存储，不创建任一云客户端或获取云凭证。
- 媒体开启时，恰好创建一个 `MediaStore`；未知提供方应启动失败，不能悄悄回退到 MinIO。
- Bucket 使用既有 `fishbook.media.bucket`；MinIO 的 Endpoint 和密钥属性保持兼容，且只在选择 MinIO 时要求。
- OSS 专属配置置于 `fishbook.media.oss`：Endpoint、Region 和 ECS 实例角色名称。OSS 启用时要求这些配置，Endpoint 必须为 HTTPS。
- 生产目标为杭州地域 OSS 内网访问；准确 Endpoint 在云资源配置时核对，不由客户端根据模糊默认值猜测。
- 客户端创建时不进行 Bucket 创建、权限设置或对象写入；应用关闭时释放 OSS 客户端和凭证客户端资源。

## 5. 身份与权限

生产优先使用 ECS 实例 RAM 角色获取自动刷新的临时凭证，不要求用户把长期 AccessKey 或私钥发送到聊天中。

凭证提供方显式选择实例角色，不使用可能拾取其他账号凭证的宽泛默认凭证链。要求使用 IMDSv2，不静默降级到 IMDSv1；不得在日志或诊断输出中显示 Token 或密钥。

Bucket 设为私有并开启阻止公共访问；对象继承私有权限。应用角色仅获授权访问这个 Bucket 的业务对象前缀，权限限于上传、读取、删除及经验证确需的附属操作。不授予 Bucket 创建、删除、ACL 修改或全账号 OSS 管理权限。

SDK 请求采用 V4 签名并启用 HTTPS 证书验证。容器内访问 IMDSv2 和凭证刷新必须在实际 ECS 环境验证；不可为了绕过连通性问题把应用改成 host 网络或将容器设为 privileged。

RAM 角色绑定是后续云资源步骤；绑定前读取现有角色，不能覆盖未知用途的绑定。

## 6. 数据流与错误处理

上传：既有服务校验登录、记录所有权、图片类型和大小后，将内部生成的对象键及内容传入 OSS 适配器。前端不能指定任意 Bucket 或对象键。

读取：先执行既有记录所有权校验，再读取 OSS 对象。响应继续通过应用返回照片内容，不返回公开或预签名对象 URL。保留内容类型，并关闭响应流；读取量限制在当前照片大小上限内，超限对象映射为存储不可用，避免无界内存分配。

删除：对象已不存在视为成功。权限不足、超时或其他云端异常不能伪装成成功，继续交由既有补偿任务处理。

适配器把云端和网络错误包装为现有 `MediaStorageUnavailableException`。对用户响应保持现有中文通用提示，不包含 Endpoint、对象键、账号信息、Token 或 SDK 错误正文。日志仅记录脱敏后的错误类别或代码，不输出凭证和请求头。

暂不迁移本地照片：本地 MinIO 不删除、不清空。以后如需迁移，需单独列出源数据、对象清单、数据库引用、校验与回滚步骤。

## 7. 测试与验收

自动化测试不需要真实云账号，不创建收费资源：

- 配置测试覆盖关闭、默认 MinIO、显式 MinIO、OSS、未知提供方和配置缺失。
- OSS 单元测试覆盖上传内容和类型、读取、响应关闭、重复删除、权限错误、超时及超限读取。
- 凭证桥接测试使用假的临时凭证，验证 Token 传递和刷新，不访问真实 IMDS。
- 验证云端错误对外脱敏，关闭客户端时释放资源。
- 回归既有 MinIO 集成测试、照片所有权隔离测试和清理任务测试。
- 验证不改数据库迁移、不改前端 API。

获得单独云操作许可后，再执行真实 OSS 冒烟验证：先只读检查目标 Bucket 的私有属性、地域、角色权限和容器内凭证刷新能力；然后在独立测试对象前缀执行上传、读取及两次删除，校验字节一致性，检查匿名访问被拒绝。清理只针对本次测试的明确对象键，不进行前缀批量删除。

只有真实 OSS 验证通过，才能声明云端照片接入可用。测试替身通过不能替代云端验收。

## 8. 发布门槛与回滚

本子项目交付代码、配置说明、固定依赖和测试结果，不等同于网站上线。

正式业务部署必须满足：RDS TLS 可用并完成证书身份校验、生产秘密已安全注入、私有照片权限通过验证、镜像已构建测试、入口访问范围明确。不得静默降低数据库加密要求。

用户已批准学习环境例外：仅使用测试及非敏感数据时，可以保留现有 RDS 并明确采用非加密内网连接；必须使用同一 VPC 的私网地址，不开通数据库外网地址，白名单只允许目标 ECS，保留普通账号、强且不复用的密码和备份。内网隔离不等于传输加密，应用与数据库间仍缺少 TLS 的保密和证书身份校验。转为真实业务或接入敏感数据前，重新评估并恢复数据库 TLS 门槛。

此例外不取消浏览器 HTTPS、生产 Secure Cookie、OSS HTTPS/V4/证书校验或照片私有权限，也不授权本子项目执行云数据库认证、迁移、购买、释放或其他云操作。实际学习部署连接配置在第二个子项目中单独实施和验收。

本地回滚恢复 MinIO 提供方即可，不涉及本地数据删除。真实 OSS 一旦写入业务照片，不能仅切换提供方而丢失读取路径；回滚应保留能读 OSS 的上一版镜像和原有 Bucket，跨存储迁移另行设计。

域名和备案阶段不得为了快速验收关闭生产 Secure Cookie 或把私有照片改为公开读。非公开验收的 TLS 入口在第二个子项目中单独设计并确认。
