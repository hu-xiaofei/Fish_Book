# FishBook：ECS 私有学习环境部署设计

日期：2026-09-15

状态：设计已于 2026-09-15 获用户审阅确认。

## 1. 目标与边界

把当前 `main` 分支部署到用户已有的杭州 ECS，并连接已有的杭州 RDS MySQL 8.4。该环境只用于学习和少量非敏感数据，在域名与备案完成前不作为公开网站发布。

本阶段保留全部现有功能，包括用户私有照片和现有管理员查看、替换、删除照片的能力。照片改存 ECS 系统盘的私有目录，不购买 OSS，不部署已停止维护的 MinIO 社区服务。

本阶段不购买或释放云资源，不开通 RDS 外网地址，不修改安全组，不删除服务器或数据库数据，不迁移本地 MinIO 照片，不建立面向公众的 HTTP/HTTPS 入口。域名、备案、公开证书和正式备份恢复演练属于后续阶段。

## 3. 总体架构

ECS 上运行两个应用容器：

1. 前端 Nginx 提供静态页面、反向代理 `/api/` 和健康检查；仅绑定宿主机回环地址的 HTTPS 端口。
2. 后端 Spring Boot 仅在 Compose 内部网络可达，连接 RDS 内网地址，并读写绑定到宿主机的照片目录。

不在 ECS 上运行 MySQL 或 MinIO。生产 Compose 必须与当前本地 `compose.yaml` / `compose.full.yaml` 分离，不能继承本地数据库、默认密码、开发管理员或公开端口配置。

浏览器访问链路为：

`本机浏览器 -> SSH 本地端口转发 -> ECS 127.0.0.1:8443 -> Nginx HTTPS -> backend:8080`

入口使用含 `localhost` 与 `127.0.0.1` SAN 的自签名证书。首次访问时浏览器会提示证书不受公共 CA 信任；证书私钥只保存在 ECS。不得通过关闭后端 Secure Cookie 或改用公网 HTTP 绕过该提示。获得域名和备案后，再切换至公网 443 与受信任证书。

## 4. ECS 文件布局与权限

部署根目录为 `/opt/fishbook`：

- `/opt/fishbook/app`：Git 工作树和生产 Compose 文件；
- `/opt/fishbook/config/fishbook.env`：数据库及管理员秘密，`root:root`、权限 `0600`；
- `/opt/fishbook/tls`：自签名证书及私钥，目录不可由应用写入，私钥权限 `0600`；
- `/opt/fishbook/data/photos`：照片与内部元数据，绑定到后端容器，应用用户可读写；
- `/opt/fishbook/releases`：部署版本记录和回滚所需的已验证提交标识，不保存秘密。

Git 仓库、Compose 文件、日志和镜像中不得包含数据库密码、管理员密码、SSH 私钥或 TLS 私钥。诊断输出不得打印完整环境变量、数据库连接串密码、Session、CSRF Token 或照片路径键。

## 5. 本地文件照片存储

扩展现有 `MediaStore`，新增 `filesystem` 提供方；保留 `minio` 和 `oss` 供本地开发或未来迁移使用。生产环境显式选择 `filesystem`，不能通过缺省值意外回退到 MinIO。

文件提供方配置独立根目录；部署过程必须预先创建该目录，媒体启用时验证它为绝对路径、可读写目录。所有对象键必须是既有服务生成的相对键，解析并规范化后仍位于配置根目录内；拒绝空键、绝对路径、`.`、`..`、越界路径和符号链接逃逸。

每个照片对象映射为一个目录，目录内分别保存内容和固定格式的 MIME 元数据。写入先在同一父目录创建唯一临时目录，完整写入并关闭两个文件后，再把整个目录原子移动到最终对象路径；最终路径已存在则失败，不能覆盖未知对象。任一步失败应只清理本次明确创建的临时目录，不能遍历或批量删除前缀。读取限制仍为 10 MiB，MIME 只允许经既有校验器确认的 JPEG、PNG、WebP。对象目录或任一组成文件不存在均映射为现有照片不存在语义；I/O 错误映射为通用 `MEDIA_STORAGE_UNAVAILABLE`，不得向响应或日志暴露绝对路径。

删除只处理规范化后的一个明确对象目录及其中两个固定名称的普通文件，拒绝跟随符号链接，并保持幂等。既有数据库事务、乐观版本、旧对象清理队列、上传补偿及管理员操作记录保持不变。Nginx 不配置照片目录的静态文件路由，浏览器只能通过现有受 Session、角色/所有权和 CSRF 保护的 API 访问。

## 6. 数据库和秘密

沿用用户批准的学习环境例外：后端通过同一 VPC 的 RDS 内网地址建立非 TLS MySQL 连接。该例外仅适用于当前非敏感学习数据；内网隔离不等于加密。转为正式业务或存储敏感数据前，必须迁移到支持 TLS 的方案并验证服务器证书身份。

数据库使用现有普通账号 `fishbook_app`，不使用 RDS 高权限账号或 root。密码由用户在受信任终端中隐藏输入，不能发送到聊天或提交 Git。首次启动前先做只读认证检查；确认目标数据库为 `fishbook` 后才允许启动应用。Spring Boot/Flyway 随首次启动应用 V1～V10 迁移；实施前记录当前 `flyway_schema_history`，只允许仓库内已审阅迁移，不执行手工删表、清库或降级脚本。

生产管理员使用独立强密码，由用户同样在受信任终端隐藏输入。仅首次空环境允许开启 bootstrap；确认管理员已经创建并能登录后，立刻关闭 bootstrap 并重建后端容器。不得使用仓库 `.env.example` 中的本地样例账号或密码。

## 7. 构建、资源和部署

目标镜像固定到已验证 Git 提交。服务器只有约 2 GiB 内存，构建前创建约 2 GiB、权限受控的交换文件，并将其持久化；创建前检查没有同名文件或既有交换配置，不能覆盖未知资源。

在 ECS 上拉取公开 GitHub 源码并构建前后端镜像。构建失败不得替换运行版本。生产 Compose 只启动前端和后端：前端端口绑定 `127.0.0.1:8443`，后端不发布宿主机端口，照片目录绑定到固定宿主机路径。容器使用非 root 用户、健康检查、`restart: unless-stopped`、日志大小与文件数限制；不使用 privileged、host network 或 Docker socket 挂载。

部署顺序为：再次只读核对 -> 安装安全更新但不擅自重启 -> 创建目录/交换空间/证书 -> 安全输入秘密 -> 数据库认证和迁移预检 -> 构建镜像 -> 启动 -> 健康检查 -> API/权限/照片冒烟测试 -> 关闭管理员 bootstrap -> 再次健康检查。

操作系统若提示必须重启，先完成部署前准备并单独向用户说明影响，再安排重启；不能在未告知的情况下中断服务器。

## 8. 验收

自动化变更须先以失败测试证明文件提供方缺失，再实现最小功能。至少覆盖：配置选择、绝对根目录要求、路径穿越和符号链接拒绝、原子写入、MIME 保存、读取上限、对象不存在、重复删除、部分写入清理和错误脱敏。然后执行完整后端测试、前端 lint/测试/构建、生产 Compose 配置解析和现有隔离浏览器测试。

云端验收使用新建的学习测试账号和一张无敏感信息的小图片：

- SSH 隧道外无法访问 Web 端口，隧道内 HTTPS 可访问；
- readiness 健康，注册、登录、退出和 Session/Secure Cookie 正常；
- RDS 迁移 V1～V10 各出现一次且无失败；
- 普通用户只能查看/替换/删除自己的照片；
- 现有管理员可以查看、替换、删除测试用户的照片，但不能借此查看钓获私有字段或收藏；
- 直接猜测照片路径不能绕过应用权限；
- 替换/删除后旧对象进入清理流程，照片目录中没有本次操作产生的已知孤儿；
- 响应、容器日志和部署记录不出现秘密、绝对照片路径或对象键。

验收只操作本次新建测试数据和明确对象，不修改或删除未知线上数据。任何一项失败都不能宣称部署成功。

## 9. 备份、回滚与已接受风险

本阶段不增加付费照片备份。照片目录位于 ECS 系统盘，因此实例/磁盘不可恢复损坏或释放会导致照片丢失；用户已明确这是少量、非重要的学习数据。部署和回滚均不得自动删除照片目录。

应用回滚保留上一已验证提交和镜像，先停止新版本，再以同一秘密和数据挂载启动上一版本。数据库迁移 V10 为前向迁移；在未验证兼容性前不能自动执行数据库降级。若新版本已经写入旧版本不兼容的数据，应停止应用并保留现场，而不是强行回滚或清库。

当前公网 SSH 22 仍按用户先前选择暂缓收紧。密钥登录、固定主机指纹和不开公网 Web 端口降低当前暴露，但不能替代后续安全组来源限制、非 root 运维账号、SSH 加固、系统盘快照和恢复演练。公开发布前必须重新处理这些项目。

## 10. 成功标准

只有同时满足下列条件，才能把本阶段标记为“已部署到云端私有学习环境”：

1. GitHub 固定提交的完整 CI 通过；
2. ECS 上只有预期容器和回环 Web 端口，健康检查通过；
3. RDS 认证、Flyway V1～V10 和应用读写通过；
4. 文件照片的权限、替换、删除、清理和管理员管理冒烟测试通过；
5. 秘密未进入仓库、镜像、日志或对话；
6. 用户获得 SSH 隧道访问命令、证书指纹、启动/停止/状态/日志和回滚说明；
7. 清楚记录域名备案、公共 HTTPS、备份恢复和 SSH 收紧仍未完成。
