# FishBook 双语 README 设计规格

- 日期：2026-08-12
- 状态：设计已获用户确认，等待书面规格复核
- 范围：仅重写仓库根目录 `README.md`

## 1. 目标

将 FishBook 的根 README 改为简体中文和英文双语文档。简体中文作为面向主要用户的默认内容，英文为国际开发者提供等价信息。README 应准确反映当前可运行功能，并让第一次接触项目的读者能够理解、启动、访问和验证 FishBook。

## 2. 文档结构

README 使用单文件双语结构：

1. 项目标题与一句话定位；
2. 顶部语言导航：`简体中文 | English`；
3. 简体中文完整说明；
4. 分隔线；
5. 英文完整说明。

两种语言采用相同章节顺序：

- 项目简介；
- 当前功能；
- 技术栈；
- 系统架构；
- 快速开始；
- 常用访问地址；
- 测试与验证；
- 项目结构；
- 当前范围与后续方向；
- 相关文档。

## 3. 内容规则

- 中文在前，使用简体中文和面向新人的清晰表达。
- 英文不是逐字硬译，但必须与中文传达相同事实。
- 说明当前已实现公开只读鱼类图鉴、12 种鱼类数据、搜索筛选、详情页、注册、登录、会话恢复、资料修改和退出。
- 明确管理员后台、图鉴写入、图片上传、收藏和钓获记录尚未实现，避免夸大项目状态。
- 技术栈版本以仓库锁定配置为准，包括 Java 21、Spring Boot 4.1、Node.js 24.18.0、React 19、TypeScript、MySQL 8.4、Docker Compose 和 Playwright。
- 快速启动优先采用完整 Docker Compose 路径，并使用 `test -f .env || cp .env.example .env`，避免覆盖已有本地环境文件。
- 明确 `.env` 只用于本地开发，不得提交。
- 停止命令保留数据卷；不在快速说明中推荐破坏性的 `down -v`。
- 提供首页、示例详情页、注册、登录、个人资料和健康检查地址。
- 测试命令提供与 CI 覆盖范围一致的本地等价流程，并说明 Playwright 需要完整服务栈；同时准确记录 CI 在 Linux 上使用 Maven 批处理模式、安装 Playwright 系统依赖，以及仅在 `main` 推送和 Pull Request 时触发。
- README 只链接仓库中实际存在的设计、运行手册和图片来源文件。
- 仓库当前没有项目许可证文件，因此不添加虚假的开源许可证声明；鱼类图片授权单独链接到来源记录。

## 4. 表达与可维护性

- 不使用依赖外部服务的徽章或装饰图片，避免失效链接和维护成本。
- 使用简洁 Markdown，不添加需要额外渲染器的复杂组件。
- 命令集中在代码块中，中文和英文保持一致，减少两套说明漂移。
- 项目结构只展示帮助新人定位的主要目录，不罗列所有文件。
- 系统架构使用一条简短文本链路说明同源访问：浏览器 → Nginx/React → Spring Boot → MySQL；MinIO 标注为已配置的基础设施，而不是当前图鉴图片的实际存储来源。

## 5. 验收标准

- `README.md` 同时包含完整的简体中文和英文部分，并可通过顶部锚点导航。
- 每个原始 HTML 语言锚点后保留空行，再开始 Markdown 二级标题，确保 GitHub 将语言名称渲染为标题而不是 HTML 块内文本。
- 所有相对文档链接都指向现有文件，所有本地 URL 与当前路由一致。
- Compose 启动、停止、健康检查和测试命令与仓库配置一致。
- README 不声称管理员功能或图片上传已经完成。
- README 不覆盖已有 `.env`，不包含真实凭据、令牌或未存在的许可证声明。
- Markdown 中没有占位符、未闭合代码围栏或明显的中英文事实矛盾。
- 本任务不修改应用代码、依赖、数据库迁移、Docker 配置或 CI。
