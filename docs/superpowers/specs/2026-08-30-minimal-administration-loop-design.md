# FishBook 最小管理员闭环设计规格

## 1. 背景

FishBook 已经交付公开只读鱼类图鉴、完整身份闭环、按账号隔离的私有收藏，以及带可选私有照片的钓获记录。身份模型和数据库已经预留 `USER`、`ADMIN` 两种角色，但系统尚未提供管理员初始化、管理授权、图鉴写入 API 或后台页面；所有鱼类资料仍由 Flyway 种子迁移直接写入，并默认对公众可见。

本阶段交付最小管理员内容闭环：安全地产生首个管理员，由管理员创建和编辑鱼类草稿，显式发布或下架条目，并确保公共图鉴只展示已发布内容。

闭环为：

```text
初始化管理员 → 登录后台 → 创建草稿 → 编辑 → 发布
      → 公共可见 → 下架 → 公共不可见 → 修改后可重新发布
```

## 2. 目标与成功标准

本阶段完成时必须满足：

- 运维人员可以通过显式启动配置幂等地初始化首个管理员，系统不开放管理员注册。
- 管理员可以查看全部状态的鱼类资料，并按关键字、发布状态分页筛选。
- 管理员可以创建完整草稿、编辑内容、发布、下架和重新发布鱼类。
- 访客与普通用户的公共图鉴搜索、筛选和详情只返回已发布鱼类。
- 普通用户无法通过页面或 API 使用任何管理能力。
- 已下架鱼类仍能被已有收藏和钓获历史解析，但不能再被新收藏或关联到新的钓获记录。
- 后端、前端和 Playwright 测试覆盖管理员完整闭环及权限边界。
- README、本地开发手册和环境变量示例准确描述管理员初始化和已实现能力。

## 3. 非目标

本阶段不实现：

- 公共鱼类封面上传、替换或公共媒体生命周期管理；管理员继续填写部署中已有的静态图片路径及署名信息。
- 鱼类物理删除、回收站或批量删除。
- 半完成草稿、自动保存、富文本编辑、内容预览或版本历史。
- 多管理员并发编辑、乐观锁或冲突合并。
- 复杂 RBAC、权限表、角色组、权限配置页面或管理员邀请。
- 批量发布、批量下架、后台统计仪表盘或内容审核流。
- 修改既有鱼类的 `slug`。

这些能力只有在最小闭环投入真实使用并出现明确需求后才评估。

## 4. 架构与模块边界

采用“独立管理用例，复用 Catalog 领域与数据”的结构：

- `catalog` 继续拥有鱼类领域实体、发布状态、公共查询规则和持久化实现。
- `administration` 应用层编排管理员创建、编辑、发布和下架用例，并通过独立的 `/api/v1/admin/fishes` Web 边界暴露管理接口。
- `identity` 继续拥有用户、密码哈希和角色；管理员初始化复用现有 `UserRepository` 与 `PasswordHasher`。
- 前端新增 `features/administration`，复用现有当前用户查询、Session、CSRF HTTP 客户端及通用表单控件。
- 不建立第二套鱼类实体、草稿表或发布时复制数据的同步机制。

后端是权限与可见性的最终裁决者。前端路由守卫和隐藏入口只改善体验，不能替代服务端授权。

## 5. 数据模型与迁移

### 5.1 发布状态

为 `fish_species` 增加：

- `publication_status VARCHAR(20) NOT NULL`
- `published_at TIMESTAMP(6) NULL`

`publication_status` 只允许：

- `DRAFT`：已保存但从未公开。
- `PUBLISHED`：当前对公共图鉴可见。
- `UNPUBLISHED`：曾进入管理生命周期、当前已下架。

迁移将所有既有鱼类设为 `PUBLISHED`，并使用其 `created_at` 作为初始 `published_at`，确保升级不会使现有公共图鉴突然变空。新建鱼类一律从 `DRAFT` 开始，`published_at` 初始为空。

### 5.2 状态转换

允许的显式转换为：

```text
DRAFT       → PUBLISHED
PUBLISHED   → UNPUBLISHED
UNPUBLISHED → PUBLISHED
```

编辑内容不改变发布状态。发布时将 `published_at` 更新为当前 UTC 时间；下架保留最近一次 `published_at` 作为历史信息。对草稿执行下架、对已发布条目再次发布或对已下架条目再次下架均视为非法转换。

### 5.3 字段与标识

管理表单覆盖现有鱼类字段：

- 基本信息：`slug`、中文名、学名、别名。
- 分类信息：科中文名、科学名，属中文名、科学名，栖息环境。
- 内容信息：外观、体型说明、栖息地说明、分布和描述。
- 图片署名：静态路径、替代文本、来源 URL、作者、许可证名称和许可证 URL。
- 展示排序。

创建后 `id` 和 `slug` 不可修改；其余内容字段可以编辑。`slug`、中文名和学名继续保持唯一。

最小版本只保存字段完整、通过校验的草稿，不允许半完成表单入库。草稿承担“未公开、可继续审阅修改”的发布门禁作用。

## 6. 查询与引用语义

鱼类读取分成两个明确语义：

- 公共 Catalog 查询：搜索、筛选选项和按 slug 获取详情只考虑 `PUBLISHED`。
- 内部及管理查询：管理列表、管理详情和解析既有私有引用可以读取全部状态。

因此：

- 草稿和已下架条目的公共详情统一返回 `404 FISH_NOT_FOUND`。
- 公开筛选选项只从已发布条目计算，避免出现点选后没有结果的分类。
- 已下架鱼类仍保留在用户已有收藏和钓获历史中，并继续显示必要的名称和图片信息。
- 新收藏和新钓获只能关联已发布鱼类；下架不会回写或删除既有私人数据。
- 系统不提供物理删除，避免破坏外键及历史记录。

持久化端口需要区分公共可见查询与不受发布状态过滤的内部引用查询，避免在单个通用 `find` 方法中隐藏不同语义。

## 7. 管理员初始化

管理员初始化由显式配置驱动，默认关闭：

```text
FISHBOOK_ADMIN_BOOTSTRAP_ENABLED
FISHBOOK_ADMIN_EMAIL
FISHBOOK_ADMIN_PASSWORD
FISHBOOK_ADMIN_NICKNAME
```

规则如下：

1. `FISHBOOK_ADMIN_BOOTSTRAP_ENABLED` 不为 `true` 时不执行任何初始化。
2. 启用时，邮箱、密码和昵称必须完整并通过现有身份校验；缺失或无效配置使应用启动失败，并给出不包含秘密值的明确错误。
3. 邮箱不存在时创建 `ACTIVE` 的 `ADMIN`，密码通过现有 BCrypt-SHA256 `PasswordHasher` 存储。
4. 同邮箱已经是 `ADMIN` 时保持现有账号和密码不变，使启动过程幂等。
5. 同邮箱已经是 `USER` 时拒绝启动，不自动提权。
6. 应用日志不得输出明文密码，也不得通过 API 回显初始化配置。

初始化只解决首个管理员入口，不是通用账号管理功能。

## 8. 授权与错误语义

Spring Security 对 `/api/v1/admin/**` 统一要求 `hasRole("ADMIN")`，所有 `POST`、`PUT` 等修改请求继续要求现有 Cookie CSRF Token。

稳定错误语义为：

| 场景 | HTTP | code |
| --- | ---: | --- |
| 未登录访问管理 API | 401 | `AUTHENTICATION_REQUIRED` |
| 普通用户访问管理 API | 403 | `ACCESS_DENIED` |
| 管理写请求缺少或携带无效 CSRF | 403 | `CSRF_INVALID` |
| 请求字段无效 | 400 | `VALIDATION_FAILED` |
| 管理条目不存在 | 404 | `FISH_NOT_FOUND` |
| slug、中文名或学名冲突 | 409 | `CATALOG_ENTRY_CONFLICT` |
| 发布状态转换非法 | 409 | `INVALID_PUBLICATION_TRANSITION` |

数据库唯一约束仍是并发条件下的最终防线；适配器或异常处理器必须把相关约束冲突稳定映射为 `CATALOG_ENTRY_CONFLICT`，不能向客户端泄露数据库细节。

## 9. 管理 API

```text
GET  /api/v1/admin/fishes?q=&status=&page=
GET  /api/v1/admin/fishes/{id}
POST /api/v1/admin/fishes
PUT  /api/v1/admin/fishes/{id}
POST /api/v1/admin/fishes/{id}/publish
POST /api/v1/admin/fishes/{id}/unpublish
```

### 9.1 列表与详情

- 列表使用固定页大小，`page` 从零开始；客户端不得覆盖页大小。
- `q` 匹配中文名、学名、slug 和别名。
- `status` 可省略，或为单个合法发布状态。
- 默认排序为最近更新优先，再按 `id` 保证稳定顺序。
- 管理详情与管理路由使用数据库 `id`，避免依赖可读标识。

### 9.2 创建与编辑

- `POST` 接收包含 `slug` 的完整创建表单；请求 DTO 不包含状态或时间字段。服务创建 `DRAFT` 并返回 `201 Created`、`Location` 和管理详情。
- `PUT` 接收不包含 `slug` 的完整可编辑内容并替换这些字段；请求 DTO 也不包含 `id`、发布状态、发布时间或审计时间。
- 所有写入用例在单个数据库事务内完成。

### 9.3 发布动作

- 发布与下架通过独立动作端点执行，不与内容编辑绑定。
- 发布前再次执行领域完整性校验。
- 动作成功返回更新后的管理详情，便于前端同步状态。
- 系统不提供管理删除端点。

请求和响应继续使用显式 DTO，不直接暴露 JPA 实体或领域对象。

## 10. 前端页面与交互

### 10.1 路由与入口

新增路由：

```text
/admin/fishes
/admin/fishes/new
/admin/fishes/:id/edit
```

登录管理员在现有用户导航中看到“图鉴管理”。管理员路由守卫的行为为：

- 当前用户查询中：显示稳定的加载状态。
- 未登录或 Session 过期：清理会话范围缓存，并带安全的 `returnTo` 跳转登录页。
- 已登录普通用户：显示无权限页面，不产生管理 API 请求。
- 管理员：渲染目标后台页面。

### 10.2 管理列表

管理列表提供：

- 关键字搜索。
- `全部 / 草稿 / 已发布 / 已下架` 状态筛选。
- 名称、学名、状态、更新时间。
- 编辑入口及上一页、下一页。

列表不提供仪表盘、批量选择或批量状态操作。

### 10.3 新建与编辑

新建页和编辑页复用同一个鱼类表单：

- 新建页只提供“保存草稿”。成功后导航到新条目的编辑页并显示成功反馈。
- 编辑页保存内容时不改变当前发布状态。
- 草稿和已下架条目显示“发布”；已发布条目显示“下架”。
- 下架前要求用户确认，因为操作会立即改变公共可见性。
- 请求进行时禁用相关按钮，防止重复提交。
- 字段校验错误显示在对应控件附近；冲突和状态错误显示页面级提示。

发布、下架或编辑成功后，前端使管理列表、管理详情、公共列表、公共筛选和受影响的公共详情查询失效。公共详情在下架后不继续显示陈旧数据。

## 11. 测试策略

### 11.1 后端

- 领域测试覆盖草稿创建、内容编辑不改变状态、发布、下架、重新发布及所有非法转换。
- 数据库迁移测试验证新列、检查约束、既有数据回填状态和发布时间。
- 持久化测试验证公共查询过滤、管理查询状态筛选、内部引用读取和唯一冲突。
- 应用服务测试验证创建、编辑和状态动作的事务行为及稳定错误。
- 授权集成测试覆盖管理员成功、匿名 `401`、普通用户 `403` 和无 CSRF 的管理员写请求。
- 管理 API 集成测试覆盖成功响应、分页、筛选、详情、验证、冲突和状态转换。
- 初始化测试覆盖默认关闭、配置不完整、首次创建、重复启动幂等和普通用户邮箱占用。

### 11.2 前端

- API 客户端测试覆盖查询参数、请求方法、CSRF 和响应映射。
- 管理员路由守卫测试覆盖加载、匿名、普通用户、管理员及非认证故障。
- 用户导航测试验证仅管理员看到“图鉴管理”。
- 管理列表测试覆盖搜索、状态筛选、分页、加载、空态和错误态。
- 共享表单测试覆盖创建、编辑、字段错误、重复提交保护、发布及确认下架。

### 11.3 端到端

Playwright 使用测试环境中显式配置的管理员完成：

1. 管理员登录并创建草稿。
2. 访客搜索不到草稿，直接访问公共详情得到未找到。
3. 管理员发布条目。
4. 访客可以搜索并打开其详情。
5. 管理员下架条目。
6. 访客再次搜索不到且无法打开详情。
7. 普通用户不能进入后台，并且直接调用管理 API 得到 `403`。

现有身份、公共图鉴、收藏、钓获和私有照片测试必须继续通过。专门的回归测试证明已下架鱼类不会破坏已有收藏和钓获历史。

## 12. 文档与运维

交付时同步更新：

- README 的功能状态、访问路径、环境变量和后续路线。
- `docs/runbooks/local-development.md` 的本地管理员初始化、首次登录和关闭初始化步骤。
- 环境变量示例中的管理员配置占位符，不提交真实密码。

运行手册应建议：首次创建成功后关闭 bootstrap 开关；初始化密码通过安全的部署秘密注入；不得在日志、Compose 文件或版本库中保存真实密码。

## 13. 实施顺序

实施按可验证的垂直切片推进：

1. 数据库发布状态与公共可见性回归。
2. 管理员初始化与服务端角色授权。
3. 后端管理创建、读取、编辑和状态动作。
4. 前端管理员守卫、导航和管理列表。
5. 共享新建/编辑表单及发布状态操作。
6. Playwright 完整闭环、文档和发布回归。

每个切片遵循测试先行，并在进入下一切片前运行相关后端或前端测试。

## 14. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 发布状态过滤误伤私人历史 | 明确拆分公共查询与内部引用查询，并添加收藏、钓获回归测试 |
| 启动配置意外提权 | 默认关闭；普通用户邮箱冲突时拒绝启动；不自动升级角色 |
| 前端隐藏入口被误当成授权 | `/api/v1/admin/**` 统一由 Spring Security 强制 `ADMIN` |
| 编辑请求意外发布或下架 | 内容保存与状态动作使用独立 API |
| 下架后公共页面显示缓存 | 状态动作成功后显式使所有相关公共查询失效 |
| 唯一约束错误泄露数据库细节 | 统一映射为稳定的 `409 CATALOG_ENTRY_CONFLICT` |
| 范围膨胀到媒体或内容平台 | 保持静态图片路径输入，不实现上传、版本、审核和批量操作 |

## 15. 完成定义

只有当以下条件全部满足时，本阶段才完成：

- 管理员初始化、授权、管理列表、创建、编辑、发布、下架和重新发布均可用。
- 公共可见性、既有私人引用和所有错误语义符合本规格。
- 后端、前端、Playwright 及现有回归测试全部通过。
- README、运行手册和环境变量示例与实际行为一致。
- 不包含本规格明确列出的非目标能力。
